# ChainReactor adapter groundwork

This directory holds reusable Engine business logic for the proposed gogo, spray, and zombie workflow. The gogo and spray API v2 adapters live in sibling `gogo_scan/` and `spray_scan/` Engine sources. This shared package is not itself an Engine package.

- gogo: `RunGogo` resolves Domain facts to bounded IPv4 candidates, runs official gogo with `-O jl -C`, and maps in-scope IP results back to original DNS names for `HostPort`. Explicit, unambiguous non-Web protocol/fingerprint evidence yields an intermediate `ServiceEndpoint` candidate. A local HTTP fixture produced `protocol:"http"`, but raw-IP HTTP evidence is not enough to authorize a later credential attempt against a named virtual host; WebsiteURLs and an endpoint contract retaining the hostname must bridge that case. The `-C` flag is required for plain JSON Lines in the verified v2.15.0 binary.
- spray: `RunSpray` consumes finalized WebsiteURLs and a materialized dictionary, runs path fuzzing with bounded controls, and maps valid JSON observations to `Directory`. It excludes the input site's baseline record and foreign origins. The verified v0.3.2 binary includes `content_type`, which is retained.
- zombie: `ZombieWebTargets` consumes the existing WebsiteURLs input file and preserves the exact hostname for Web authentication. `RunZombieLocalVerification` accepts `service://host:port` or `service://ip:port` targets and bounded username/password files. The official binary was verified against a local `auth.localhost` Basic Auth target, including Host-header routing. Its JSON contains plaintext passwords; `ParseZombieJSONL` returns only redacted valid-credential or anonymous-access findings and drops uncertain mode-2 checks. The CLI has no reliable anonymous-only switch, so this runtime always requires an explicitly chosen test credential set and remains limited to isolated local verification until paced execution policy and a persisted `AuthFinding` result contract exist. Real production passwords additionally require a protected credential path.

All parsers require a caller-supplied scope predicate, bound each record to 4 MiB, and return accepted/skipped counts. Runtime callers must treat wholly rejected output as a tool or contract failure when they expected observations.

Official release binaries were downloaded outside the repository and verified against their release checksum files. The isolated loopback integration tests can be repeated with `CHAINREACTOR_GOGO_BINARY`, `CHAINREACTOR_SPRAY_BINARY`, and `CHAINREACTOR_ZOMBIE_BINARY` set to those executables. No binary or credential fixture is committed.

The corresponding official Linux arm64 release binaries were checksum-verified and started successfully inside the development Docker daemon's linux/arm64 Server image with networking disabled. Gogo and spray Runtime Images also passed local build-time conformance; their Package v2 archives were validated and registered in the development Server. A task-level Agent → Engine API v2 → Server result scan has not yet been completed.

Strictly validated `engine.v5` configuration drafts live in `proposals/engine-manifests/`. Gogo and spray now have installable definitions in their own Engine directories; these proposal copies are design snapshots. Zombie's draft intentionally has no production credential resource declaration because the current ordinary wordlist kind is not an acceptable password resource. The existing Agent can already materialize WebsiteURLs, so adding this Web target route does not itself require Agent source changes; a new input role or protected resource would.

The existing `/scan/config/engines/` page installs an immutable OCI Engine Package; `/scan/config/workflows/` creates and edits a workflow using installed Engines. The proposed three-Engine definition lives at `proposals/chainreactor.scan-workflow.json` until zombie is installable. Moving it into `extensions/workflows` now would fail Server startup during built-in workflow synchronization. Gogo and spray are registered in the local development database; the full workflow is not yet created.
